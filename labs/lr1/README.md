# Лабораторная работа №1: AVL-множество и словарь

Проект реализует AVL-множество `AvlSet<T>` для типов с операцией `<` и словарь `AvlDictionary<Key, Value>` для значений, которым сравнение не требуется. Словарь использует сравнимый ключ и хранит значение без сравнения. Узлы дерева владеют дочерними узлами через `std::unique_ptr`; контейнеры STL для хранения элементов не применяются.

Документ проектирования работы: [DESIGN.md](DESIGN.md).

В [`avl_set.hpp`](include/avl_set.hpp) находятся правила AVL-множества, его операции и текстовый формат. Контракты коллекции, перечисления и словаря вынесены в отдельные заголовки. [`avl_dictionary.hpp`](include/avl_dictionary.hpp) реализует словарь поверх AVL-множества; `TreeEnumerator` реализует inorder-перебор собственным связным стеком. Меню вынесено в [`tree_console.cpp`](src/tree_console.cpp), замеры — в [`benchmark.cpp`](src/benchmark.cpp), запуск режимов — в `main.cpp`. Предметные типы для демонстрации определены в `value_examples.hpp`.

## Возможности

- вставка, поиск, удаление, AVL-балансировка, высота, размер и доступ к элементу по индексу;
- шесть вариантов обхода, `map`, `where`, `reduce`, слияние, копирование поддерева и проверка его вхождения;
- запись и чтение структуры в формате обхода, например `{К}(Л)[П]`; строки экранируются кавычками;
- работа AVL-множества с целыми и вещественными числами и строками; словарь хранит комплексные числа, указатели на функции и записи студентов и преподавателей по целочисленным ключам;
- ручное меню и генерация случайных значений с количеством, границами диапазона и seed;
- замеры вставки, поиска и удаления на случайных перестановках, до `10^8` ключей при достаточной памяти.

Для вставки, поиска, удаления и индексного доступа сложность `O(log n)` в худшем случае. Сравнение двух множеств выполняется за `O(n)` через два перечислителя. Проверка поддерева ищет его уникальный корень за `O(log n)`, затем сравнивает `m` ветвей за `O(m)`. Обходы и `reduce` работают за `O(n)`. `map`, `where` и слияние строят результат вставками и занимают `O(n log n)`. Память дерева — `O(n)`.

## Сборка и проверки

Из каталога проекта:

```sh
make
make run
make test
make test-sanitize
```

Проверки разделены на шесть групп и содержат более 100 тысяч утверждений, в том числе 20 000 случайных вставок и удалений со сравнением с независимой упорядоченной моделью. Проверяются все типы из варианта, баланс после поворотов, интерфейсы, недействительность перечислителя после изменения дерева, операции с поддеревьями и чтение/запись во всех шести форматах. Счётчик живых узлов компилируется только в тестовой сборке; `test-sanitize` включает AddressSanitizer и UndefinedBehaviorSanitizer.

## Бенчмарк

```sh
make benchmark MAX_SIZE=1000000 SEED=20261116
make graph
```

По умолчанию выбираются 20 размеров от `10^4` до `10^8`; `MAX_SIZE` ограничивает верхний размер конкретного запуска. Для воспроизводимости порядок ключей задаётся seed. Результаты запуска сохраняются в `benchmark.csv`, график — в `benchmark.svg`. Поиск AVL сравнивается с бинарным поиском в отсортированном массиве, выделенном через `std::unique_ptr<T[]>`; контейнеры STL не используются.

Последний замер выполнен с seed `20261116`, пределом `10^7` и случайным порядком вставки, поиска и удаления. Наибольший полностью пройденный набор — 8 858 668 ключей. Время указано в миллисекундах; это один запуск на локальной машине, поэтому значения могут меняться при повторении.

| Ключей | Вставка AVL | Поиск AVL | Бинарный поиск в массиве | Удаление AVL |
| ---: | ---: | ---: | ---: | ---: |
| 10 000 | 1.85 | 0.69 | 0.67 | 2.29 |
| 784 760 | 245.29 | 175.25 | 52.80 | 306.67 |
| 8 858 668 | 7 745.19 | 5 764.57 | 1 978.42 | 8 217.16 |

В этом прогоне поиск по массиву оказался быстрее поиска по AVL-дереву за счёт последовательного хранения и меньшего числа переходов по памяти. Массив служит только ориентиром для поиска: вставка и удаление в отсортированном массиве требуют сдвигов `O(n)`, тогда как AVL сохраняет `O(log n)` для трёх основных операций.

Пример меню: выберите пункт `14`, укажите количество значений, минимум, максимум и seed. Повторяющиеся случайные числа считаются одной записью, поскольку структура является множеством.
